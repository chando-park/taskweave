# 재승인 기준

다음 중 하나라도 발생하면 구현을 중단하고 재승인받는다.

- 최초 원인이 틀렸거나 핵심 원인이 추가로 발견됨
- 승인 목록 밖의 주요 파일 또는 다른 저장소 수정이 필요함
- Public API 또는 SDK 외부 동작이 변경됨
- 서버 API, BLE Command/Packet, 데이터 저장 형식이 변경됨
- 구버전 호환성 또는 migration이 달라짐
- 사용자에게 보이는 동작이 승인안과 달라짐
- 테스트 전략이나 완료 조건을 변경해야 함
- 데이터 손실이나 복구 불가능한 작업 가능성이 발견됨
- 승인 뒤 추가된 사용자 변경이 새로운 상태·콘텐츠 형식·API 분기를 나타내며 승인된 동작 범위를 넓힘
- 반드시 수정·삭제해야 하는 기존 변경의 의도를 현재 요청·Workplan·테스트·주석·diff에서 확인할 수 없음

다음은 일반적으로 재승인이 필요하지 않다.

- 같은 파일 안의 명백한 컴파일 수정
- 기존 규칙에 따른 이름·접근 제어 조정
- 승인된 동작을 검증하기 위한 좁은 테스트 보강
- formatter가 만든 승인 파일 내부의 기계적 변경
- 승인된 API와 동작 범위 안에서 상태 커버리지를 넓히지 않는 단순 fixture·문구 추가

판단이 애매하면 변경의 크기가 아니라 외부 동작과 계약의 변화 여부를 기준으로 삼는다.
