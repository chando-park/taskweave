# Feature Approval Memo Template

신규 기능 main은 `workplan_schema: approval-memo-v1`을 사용하고 다음 판단만 담는다.

## 이유와 기대 동작

원문으로 확인한 현재 문제와 구현 뒤 사용자가 관찰할 동작을 짧게 적는다.

## 변경 컨셉

핵심 코드가 어떤 책임 경계와 데이터·상태 흐름으로 바뀌는지 한두 문장으로 적는다. 승인 검사가 이를 코드·검증 계획과 함께 사용자에게 자동 출력한다.

## 핵심 코드

각 주요 파일·심볼에 대해 실제 현재 코드 또는 정확한 삽입 지점과 제안 코드를 caller/assembly가 보이게 병치한다. public API/type, state/action/branch가 적용되지 않으면 구체적 이유를 적는다.

여러 행동이 이어지면 선택적 `## 구현 구상`에서 파일 순서보다 동작 순서로 핵심 코드를 보여 준다. 응답 매핑, 도메인·상태 처리, 호출 또는 화면 연결, 제거할 이전 경로 중 실제 변경 항목만 골라 적는다. 코드 fence는 실제 대상 언어를 쓰고, 현재 확인된 코드와 구현 제안을 분명히 나눈다. 작은 변경에 별도 섹션이나 같은 개수의 코드 블록을 강제하지 않는다.

## 변경 파일

파일·심볼, 책임과 함께 바뀌는 caller를 적는다.

## 제외 범위

바꾸지 않을 계약·저장소·cleanup·조합을 적는다.

## 최소 검증

변경, 실패 위험, 직접 방법·식별자와 통과 기준을 적는다. UI이면 tier, 영향 View·state·Snapshot과 source/candidate 비교를 포함한다.

새 메모의 `## 검증 계획`은 한 검증당 표 한 행으로 쓴다. 열은 `검증 대상/실패 조건 | 방법·파일/식별자 | 실행 명령 | 통과 기준`이다. 기존 테스트는 실제 식별자, 신규 테스트는 만들 파일과 이름을 적는다. 실행 제외 항목은 `- 제외: 대상과 이유`로 짧게 기록한다.

## 승인

준비된 revision과 구현 승인 여부를 적는다.

긴 코드가 꼭 필요할 때만 `Details/plan-code.md`를 연결한다. 결과·지식 평가 문서는 구현 전에 만들지 않는다.
