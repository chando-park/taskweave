# 코드 흐름 시각화와 근거 설명

코드 Workplan은 계획 작성이 끝나 승인안을 제시하기 직전, 그리고 승인 후 구현 결과를 보고하기 직전에 이 스킬을 적용한다. 사용자의 최종 완료 요청까지 설명을 미루지 않는다. 독립된 코드 분석·흐름 시각화 요청에도 사용할 수 있다. 주목적은 파일 생성이 아니라 사용자가 실행 순서·데이터·분기와 변경 영향을 그림으로 이해하는 것이다. HTML은 그림과 근거를 연결해 보여 주는 수단이다. 제품 코드 수정·테스트 실행·승인·Git/외부 게시 권한을 추가하지 않는다.

## 현재 단계의 근거만 사용

- 분석: 사용자가 지정한 시작점과 실제 확인한 파일·심볼·호출자·원천을 사용한다. 확인하지 않은 관계는 추론·미확인으로 표시한다.
- 계획: 현재 Workplan의 전체 변경 대상·실제 현재 코드·제안 코드·검증 계획을 사용한다. 아직 구현하거나 실행하지 않은 코드를 '최종 코드', 테스트를 '통과'로 쓰지 않는다.
- 결과: 이번 승인 범위의 실제 diff·신규/삭제 파일·기존 실행 결과를 사용한다. 범위 밖 사용자 변경을 이번 구현으로 소개하지 않으며 계획 코드로 실제 구현을 대신하지 않는다.

이미 확인한 같은 코드·결과를 재사용한다. 새 symbol·caller 조사가 필요할 때만 [Serena 절차](../../references/serena-code-intelligence.md)를 적용하고, 도구 실패를 광범위한 검색으로 숨기지 않는다. 근거가 없는 동작이나 결과는 만들지 않는다.

## 전체 흐름을 먼저 보여 주기

확인한 근거에서 시작 이벤트 → 호출 주체·함수 → 입력/변환/저장/전송 → 최종 결과를 먼저 시각화한다. 시간 순서는 시퀀스, 조건은 흐름도, 상태 변화는 상태도를 선택한다. 상자에 파일명만 나열하지 않고 '누가 무엇을 하는지'를 표시하며 화살표에는 호출·전달 데이터·분기 조건을 적는다.

실제 존재하는 성공·실패·취소·보류·재시도 경로를 그림에 표시한다. 분기를 본문 각주로만 남기거나 성공 경로만 그려 전체 동작처럼 보이게 하지 않는다. 계획은 현재 → 제안의 달라지는 경로를, 결과는 실제 구현과 검증된/미검증 경로를 구분한다. 관련 없는 경로나 계층은 발명하지 않는다.

그림의 각 단계·분기에서 해당 실제 코드, 변경 이유, 관련 테스트·결과로 이동할 수 있게 한다. 사용자가 전체 흐름 → 궁금한 단계 선택 → 코드·이유·검증 확인 순서로 읽도록 한다. 그림과 코드가 연결되지 않은 장식용 도식이나 긴 코드 문서 뒤에 붙인 부록으로 끝내지 않는다.

## 흐름에 연결하는 빠짐없는 코드 설명

[공통 설명 원칙](../../references/implementation-handoff.md#공통-설명-작성-원칙)과 [코드 설명 기준](../../references/verification-evidence.md#구현-결과의-빠짐없는-설명)을 읽는다. 계획에서는 같은 기준을 **예정 변경 전체**에, 결과에서는 **실제 변경 전체**에 적용한다.

1. 이번에 추가·변경·삭제할/한 파일과 타입·프로퍼티·함수·분기 전체를 그림의 해당 단계·분기와 코드 설명에 연결한다. 전체 목록은 탐색용으로 제공하되 첫 화면을 긴 목록으로 가리지 않는다. 파일 목록이나 '핵심 몇 개'만 설명하고 나머지를 생략하지 않는다.
2. 각 항목의 실제 현재/변경 코드, 역할, 누가 언제 호출하는지, 입력·조건·처리·출력, 변경 이유와 유지 동작을 쉬운 한글로 설명한다. enum은 각 case·연관 값·판정 위치·상태별 처리, 공개·동시성 선언은 필요한 이유도 보여 준다. 신규 코드는 삽입 위치·호출부를, 삭제는 제거 이유·대체 경로를 연결한다.
3. 시작 이벤트에서 최종 결과까지 실제 호출 순서와 상태·데이터 이동을 보여 준다. 해당 성공·실패·취소·재시도 경로를 구분하고 명시하지 않은 기능을 설명 과정에서 새로 설계하지 않는다.
4. 동일한 기계적 변경은 해당 파일·심볼과 공통 이유를 적어 묶는다. 서로 다른 동작은 묶어서 숨기지 않는다. 전체 파일 낭독 대신 설명에 필요한 완전한 코드 단위를 사용한다.

## 검증 근거와 표시 수단

계획은 테스트 파일/케이스·입력·확인 동작·통과 기준과 제외 이유를 설명한다. 결과는 [테스트·커버리지 기록](../../references/verification-evidence.md#테스트커버리지-기록)으로 실제 테스트 목록·결과·집계·커버리지 범위와 수치 또는 `미측정 — 이유`·미검증 범위를 함께 보여 준다. 기존 로그를 사용하며 이 보고를 위해 테스트를 다시 실행하지 않는다.

복잡한 호출·상태·데이터 경계는 [코드 흐름 시각화 기준](../../references/code-explanation-html.md)으로 그림을 중심에 둔 HTML을 작성·갱신한다. 단순한 수정에는 파일을 강제하지 않고 짧은 흐름·코드 설명으로 충분하다. 기존 Workplan의 `Artifacts/` 또는 허용된 산출물 위치를 사용하고 제품 `docs/`·설치 캐시에 작업 보고서를 만들지 않는다.

보고 직전 '시작부터 결과까지 그림으로 따라갈 수 있는가, 모든 변경·조건과 실제 코드·이유·테스트가 연결되는가'를 확인하고 누락만 보완한다. 대화에도 가장 중요한 흐름과 바뀐 경로를 먼저 설명하고 전체 변경 목록·주요 코드·검증 요약·시각화 링크를 연결한다. 긴 설명은 같은 Workplan의 기존 영역에 두고 중복 문서를 만들지 않는다. HTML 존재·보기 좋은 배치·링크 수를 이해 가능성이나 제품 검증 통과로 대신하지 않는다. 별도 schema·검사·추가 승인·검토 agent를 필수로 만들지 않는다.
