# 코드 흐름 시각화와 근거 연결

Codex·Claude가 코드의 실행 순서·데이터 이동·조건 분기와 변경 영향을 먼저 시각화하고, 그림에서 실제 코드·변경 이유·테스트로 연결하는 공통 기준이다. HTML은 이를 표시·보관하는 수단일 뿐 산출물 생성 자체가 목적은 아니다. 기존 연결 호환을 위해 파일명은 유지한다. 별도 MCP 명령·서버·빌드 시스템·외부 시각화 서비스를 전제로 하지 않는다.

## 언제 사용하는가

여러 계층·파일 사이의 호출, 비동기 수명, 상태별 분기, 데이터 이동 또는 현재/제안 구조의 차이를 텍스트만으로 따라가기 어려운 코드 작업에 사용한다. 사용자가 HTML 설명을 요청한 경우에도 적용한다. 단순 문구·수치·국소 함수 수정이나 Workplan이 의무라는 이유만으로 강제하지 않는다. 사용자 요청이 대화 설명만이거나 파일 생성을 금지하면 그 범위를 우선한다.

설명을 위해 구현 계층·기능·테스트를 추가하거나 이미 확인한 코드를 전수 재조사하지 않는다. 작업 중 읽은 실제 코드·diff·직접 결과를 재사용하고, 부족한 호출 관계만 해당 코드 탐색 절차로 보완한다. 코드가 복잡하다는 사실을 예쁜 그림으로 숨기거나 임의로 설계를 단순화해 표현하지 않는다.

## 단계별 보여줄 내용

| 시점 | 먼저 보여줄 시각화와 근거 | 기본 파일명 |
| --- | --- | --- |
| 복잡한 코드 분석 | 현재 시작점부터 결과까지의 호출·데이터·조건·오류/취소 경로 → 단계별 실제 코드·확인/추론/미확인 | `Artifacts/code-analysis.html` |
| 복잡한 변경 계획 | 현재와 제안의 흐름 차이·유지/제거/추가 경로 → 단계별 현재/제안 코드·이유·검증 계획 | `Artifacts/code-plan.html` |
| 승인 후 구현 결과 | 실제 구현된 흐름·분기와 검증된/미검증 경로 → 단계별 변경 코드·이유·테스트 결과·커버리지 | `Artifacts/code-result.html` |

이번에 수행한 단계만 작성한다. 분석 요청에 계획·결과 파일을 미리 만들지 않고, 기존 같은 단계 HTML이 있으면 최신 상태로 갱신한다. 계획 코드는 '제안·미구현', 실행 전 테스트는 '계획·미실행'으로 표시한다. 구현 결과는 [빠짐없는 코드 설명](verification-evidence.md#구현-결과의-빠짐없는-설명)과 [테스트·커버리지 기록](verification-evidence.md#테스트커버리지-기록)을 따른다.

## 그림과 실제 코드 연결

- 첫 화면은 짧은 범위 설명 뒤 전체 흐름을 중심에 둔다. 긴 변경 목록·코드·시험 집계로 그림을 아래로 밀지 않는다. 시간 순서는 시퀀스, 조건은 흐름도, 상태 전이는 상태도, 책임·의존 관계는 구조도를 선택한다. 긴 그림 하나로 압축하지 말고 읽을 수 있는 단위로 구분한다.
- 노드는 실행 주체·실제 동작, 화살표는 호출 순서·전달 데이터·조건을 보여 준다. 실제 있는 성공·실패·보류·취소·재시도 분기를 그림 안에 표시하고 본문 각주로만 숨기지 않는다. 조건과 연결 방향은 코드에 맞춰 확인하며 그림에 없는 처리를 테스트 통과로 대신하지 않는다.
- 다이어그램의 각 단계·분기를 문서 안의 해당 코드 설명으로 연결한다. 설명에는 실제 저장소·상대 파일 경로·심볼·조회한 revision과 필요한 코드 조각을 표시하고, 원본 파일 또는 기존 Workplan 근거 위치도 연결한다. 번호·앵커 형식은 자유이며 새 graph/schema는 요구하지 않는다.
- 단계나 분기를 선택하면 그 부분의 '무슨 일 → 실제 코드 → 왜 이렇게 바꿨는가 → 어떤 테스트가 확인하는가'를 바로 볼 수 있게 한다. 내부 링크나 최소한의 선택 패널을 사용하고 테스트가 없으면 미검증·이유를 표시한다. 코드·테스트 목록은 그림의 근거이지 그림을 밀어내는 별도 주인공이 아니다.
- 각 타입·함수·분기에 누가 언제 호출하는지, 입력·조건·처리·출력과 변경 이유를 쉬운 한글로 설명한다. enum case·연관 값과 성공·실패·취소 처리는 실제 조사 범위에 맞춰 표현한다. 확인하지 않은 API 응답·패킷 예시·실행 결과를 발명하지 않는다.
- 현재/제안/실제 구현, 관찰/추론/미확인을 텍스트로 구분한다. 실제 없는 DB·서버 호출이나 중간 계층을 연결하지 않는다. 그림만으로 코드 설명을 대체하거나 코드 덤프만 붙이지 않는다.
- 결과 단계는 실제 실행한 테스트 파일·케이스별 확인 동작·통과/실패/skip/미실행, 전체 집계, 커버리지 범위·기준·실측값 또는 `미측정 — 이유`를 연결한다. 많은 테스트의 상세는 기존 검증 영역을 링크하고 핵심 결과·집계·미측정 이유는 HTML 안에서도 보여 준다. 코드 변경과 직접 검증을 서로 연결하되 테스트가 없는 변경도 숨기지 않는다.

## 파일과 사용자 보고

현재 Workplan이 있으면 그 폴더의 `Artifacts/`에 저장하고 본문·상세 코드·기존 검증 영역에서 상대 링크로 연결한다. HTML은 사람이 이해하기 위한 표현이며 승인·작업 상태·원본 로그의 별도 정본이 아니다. 기존 기록의 근거를 재사용하고 같은 장문의 설명·테스트 표를 Markdown과 HTML에 중복 관리하지 않는다. 근거가 바뀌면 해당 설명·링크도 갱신한다.

제목·티켓은 [같은 작업의 MD 기준](workplan-layout.md#승인받을-자료를-한-작업으로-연결하기)을 사용한다. HTML의 `<title>`·첫 주제목에 별도 이름을 만들지 않으며 단계별 코드·변경 이유·검증 계획이 같은 MD의 현재 안과 일치하는지 확인한 뒤 승인안을 제시한다. 뷰어에 이미 있는 코드 흐름 탭으로 연결하며 사용자가 다시 HTML 요청을 해야 뒤늦게 만드는 별도 작업으로 취급하지 않는다.

Workplan이 없으면 사용자가 지정한 산출물 위치나 호스트가 제공하는 작업 산출물 영역을 사용한다. 위치가 없을 때만 저장 위치를 묻고 HTML 때문에 새 Workplan·프로젝트 등록을 요구하지 않는다. 제품 저장소의 `docs/`, 설치 캐시, 다운로드 폴더를 임의로 기록 위치로 삼지 않는다.

대화에는 컨셉·전체 변경 목록·주요 실제 코드와 확인 결과를 설명하고 HTML 파일의 절대경로 링크를 제공한다. HTML 링크 하나로 승인안이나 구현 결과 응답을 대체하지 않는다. HTML 생성은 제품 코드 수정·구현 승인·검증 통과·외부 게시·사용자 최종 완료를 뜻하지 않는다.

## 가벼운 HTML 작성과 확인

기본은 단일 HTML 안의 CSS·SVG와 필요한 코드·표·내부 앵커다. 한국어 `lang`, SVG 제목·설명, 키보드로 열 수 있는 링크·접기 기능을 사용한다. 좁은 화면에서도 글자를 읽을 수 있도록 구역을 나누고 코드·넓은 도식은 해당 영역만 스크롤한다. 색상만으로 상태를 구분하지 않는다. 상호작용이 필요할 때만 최소한의 로컬 JavaScript를 사용한다.

외부 폰트·CDN·분석 스크립트·업로드 없이 열리게 하고, 보고서 코드·로그는 HTML escape해 텍스트로 표시한다. 인증값·사용자/의료 원문·회사 민감정보를 복사하지 않는다. 공유용 문서에는 개인 절대경로 대신 저장소 상대경로와 revision을 쓰고 공개 게시 권한을 추정하지 않는다. 다른 호스트의 전용 시각화 도구를 필수 의존성으로 만들지 않는다.

시작점에서 각 결과까지 사용자가 그림을 따라갈 수 있는지, 분기 조건·데이터·변경 경로가 실제 코드와 맞는지 먼저 확인한다. 대표 단계·실패 분기를 선택해 코드·이유·테스트 근거에 도달하는지 확인한다. 브라우저 미리보기가 가능하면 한 번 열어 잘림·겹침·깨진 링크도 확인하고 불가능하면 미확인을 알린다. HTML 형식 검사·렌더러 설치·문서 hash·별도 검토 agent를 제품 구현이나 완료의 추가 허가 조건으로 만들지 않는다. 표시 문제가 생겨도 실제 작업 결과와 가능한 흐름 설명을 먼저 전달하고 남은 문서 문제만 밝힌다. 보고용으로 앱 빌드·Snapshot·테스트를 다시 실행하지 않는다.
