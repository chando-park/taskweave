# 프로젝트 폴더만 지정하는 초기 설정

[공통 작업 흐름](../../references/task-workflow.md)으로 이번 요청의 종류·진행 방식·기록 필요를 구분한다. 일반 문서 요약·대본 수정은 프로젝트 등록·Git·MCP 없이 할 수 있다. 설정을 끝내야 모든 작업이 가능하다고 말하지 않는다.

## 필요한 항목만 설정

- 초기 설정을 요청하면 기본 관리 위치 ~/.local/share/ai-workflow/workspaces/personal/projects/를 준비한다. 기록 위치·프로젝트 ID·실행 신뢰를 처음부터 묻지 않는다. 기존 설정의 관리 위치·등록·외부 기록 경로는 유지한다. 설치 캐시 안에는 기록하지 않는다.
- 사용자에게 프로젝트들이 들어 있는 폴더만 묻고 발견 목록을 보여 준 뒤 등록을 확인한다. 먼저 공유 설정과 이미 연결된 뷰어의 Workplans 상위 작업공간에서 workspace.yaml·workspace.local.yaml의 실제 저장소 경로를 대조한다. 기존 회사 프로젝트가 있으면 그 ID·Workplan·지식·지침 위치를 재사용한다. 조회·저장·뷰어는 같은 projectCatalog 연결을 쓰며, Codex의 표시 이름이나 폴더명만으로 별도 개인 등록을 만들지 않는다. 여러 회사가 같은 저장소를 가리키면 사용자에게 선택을 묻는다. 기존 연결이 없을 때만 폴더명으로 ID를 생성하고 관리 영역에 기록 폴더를 만든다. 소스 폴더는 바꾸지 않으며 실행 신뢰는 별도로 확인한다.
- 호스트에서는 설치본의 mcp/src/installation.mjs를 node로 실행한다. 터미널 초기 설정은 --client both --setup, 대화에서 폴더·등록 승인을 받았다면 --client both --setup --project-root <승인한 절대경로> --apply를 사용한다. Codex·Claude는 같은 사용자 설정을 공유하므로 호스트별 기록 복사본을 만들지 않는다. 명령이 실패하면 이유와 미완료만 알리고 수동 JSON을 추측해 덮어쓰지 않는다. 일반 작업에 MCP 설정 도구 호출을 선행 조건으로 삼지 않는다.
- 연결을 원할 때 CLI의 --integrations serena,figma,jira --dry-run 또는 호스트의 지원 도구로 선택한 호스트/서비스만 확인한다. 모르는 상태는 unknown으로 두고 표시 이름만 다르다는 이유로 중복 설치하지 않는다.
- 부족한 설치·등록만 미리 보여 주고 확인한 동작만 해당 호스트의 지원 도구/설치 프로그램으로 수행한다. 로그인은 공식 호스트 화면에 맡기며 토큰·인증 파일을 채팅이나 다른 호스트에 복사하지 않는다.
- AI가 해당 호스트의 Figma/Jira/Serena 도구로 선택 자료를 최소 읽기 확인한다. 실제 읽은 자료·호스트·결과만 허용된 기록 위치에 record_save로 남길 수 있다. 도구 목록 노출만으로 읽기 성공이라고 하지 않으며 인증값은 기록하지 않는다.

기본 MCP 업무 도구는 context_read, task_current, record_save 세 가지다. 설치·등록·로그인을 MCP가 대신한다고 가정하지 않는다. 일반 문서 작업은 MCP 없이 계속할 수 있다.

기존 기록은 원래 위치에 연결하고 이동·변환하지 않는다. 잘못된 개인 등록을 회사 쪽에 연결해 달라는 요청은 SettingsStore.linkExistingProject로 처리한다. 설정 백업·이전 ID 연결을 남기고, 이미 있는 회사 문서를 덮어쓰거나 중복 생성하지 않는다. 원문은 보존하고 필요한 기록만 연결한다. 미완료 항목만 재개한다. 회사 정책·관리자 제한을 우회하거나 Jira 시험 티켓·Figma 시험 파일을 만들지 않는다. 우리 MCP가 다른 서버를 대신 호출한다고 가정하지 않는다. 설정·플러그인 파일 저장은 새 세션의 도구 노출·인증 성공과 별개다.

사용자가 CDPower 또는 이전 Taskweave 제거를 요청하면 /taskweave:uninstall을 사용한다. 설치 ID와 스킬 접두어 taskweave는 기존 업데이트 호환을 위해 유지한다.
