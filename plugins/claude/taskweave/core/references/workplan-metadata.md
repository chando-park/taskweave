# Workplan Metadata

## 수명주기 시각

- `created`, `updated`, `approved_at`, `verified_at`, `completed_at`은 초와 UTC offset을 포함해 따옴표로 감싼 ISO 8601 문자열을 사용한다. 예: `"2026-08-19T15:48:04+09:00"`.
- 새 문서의 작성·수정 시각은 사용자의 현지 시간대를 사용한다. 호스트가 제공한 사용자 시간대가 있으면 실행 서버의 시간대보다 우선하고, 없으면 사용자 환경의 시간대를 확인한다. 현재 시스템 시각을 도구로 조회해 해당 시간대로 변환하며 LLM이 시각을 추정하지 않는다. 현재 사용자 환경은 `Asia/Seoul`이지만 다른 컴퓨터에서도 한국 시간을 고정하지 않는다.
- 문서에 시간대를 별도로 기록할 필요가 있으면 `timezone: "Asia/Seoul"` 같은 IANA 이름을 사용하고, 날짜·시·분·초·offset을 함께 보존한다. Codex와 Claude는 같은 사용자 시간대와 기록을 사용한다. 외부 원문의 발생 시각은 원본을 보존하며 문서 작성 시각과 섞지 않는다.
- `created`는 최초 작성, `updated`는 실제 수정, `approved_at`은 실제 사용자 승인, `verified_at`은 실제 검증, `completed_at`은 실제 완료 처리 시각이다. 현재 시각으로 과거 승인·검증·작성 이력을 덮어쓰지 않는다.
- 뷰어는 시각이 있는 기록을 사용자의 현지 시간으로 변환해 초와 시간대 이름까지 표시한다. UTC 내부 정렬값은 사용할 수 있지만 사용자 표시를 UTC로 고정하지 않는다. 날짜만 있는 과거 기록에는 임의의 자정 시각을 표시하지 않고 시각 미기록임을 알린다. 파일 수정 시각을 사용한 경우에는 문서의 작성·완료 시각이 아니라 파일 수정 시각임을 구분한다.
- 상태, 승인 범위 또는 검증 근거가 바뀔 때마다 `updated`를 갱신한다.
- 기존 `YYYY-MM-DD` 값은 읽기 호환성을 유지하고 일괄 변환하지 않는다. 정확한 과거 시각이나 Raw 원본 날짜를 추정하지 않는다.
- 따옴표 없는 YAML timestamp는 parser가 `Time` 객체로 해석할 수 있으므로 사용하지 않는다.
- `2026-08-21`부터 생성되거나 갱신되는 Workplan은 위 형식을 강제한다.
- 정확한 승인 시각을 복구할 수 없는 legacy 문서만 `lifecycle_timestamp_precision.approved_at: date_only_unrecoverable`과 사유를 사용할 수 있다. 새 승인 기록에는 허용하지 않는다.

상태·경로·본문 분리 규칙은 [Workplan Layout](workplan-layout.md)을 따른다.
