# 개인 작업 원칙 반영

개인 위키는 생각과 근거의 원본이고 Runtime은 실행 설정이다. 모든 생각을 전역 규칙으로 만들지 않는다. 회사 제품 사실·미확정 추정을 개인 원칙으로 옮기거나 회사 문서·코드 저장소를 명시 요청 없이 수정하지 않는다. 인증·개인 식별 정보를 설정에 넣지 않는다.

## 검토와 변경

1. 대상 노트·요청을 읽고 관련 AGENTS·Skill·reference만 확인한다. 중복·상충·적용 범위·반복 가능성을 검토한다.
2. [승격 대상 분류](references/promotion-targets.md)로 원본을 고른다. AGENTS는 짧은 공통 행동, Skill은 작업 절차, reference는 필요한 상세, script/Hook은 결정적 반복 검사에 사용한다.
3. [실행 계약](../../references/execution-contract.md)과 [위험 분류](../../references/risk-routing.md)로 변경 승인 경로를 선택하고 실제 현재/제안 문구·영향 파일·검증을 보여 준다. 질문은 읽기 전용이며 최초 수정 요청만으로 필요한 승인 단계를 우회하지 않는다.
4. Skill 작성·수정은 환경에 제공된 $skill-creator로 선택 조건·권한·조건부 자료·실행 연결을 확인한다. 실제 반복 실패와 사용 근거 없이 예외 규칙을 늘리지 않는다.
5. 승인 범위만 적용하고 Settings Change Log.md에 날짜·원본·위치·이유를 남긴다. 새 규칙이 불필요한 질문·승인·검증을 늘리지 않는지 확인한다.

## 설치 확인

기존 본문·reference만 바꾸고 공유 링크가 유효하면 원본 연결을 확인한다. 새 Skill·명령·agent·설치 위치가 추가·변경되었거나 연결 문제가 있을 때만 install과 설치 전용 doctor를 실행한다. 과거 Workplan 전수 검사를 본 작업의 선행 조건으로 만들지 않는다. 선택한 문서는 끝까지 읽고 무관한 회사 정책·자료를 복제하지 않는다.
