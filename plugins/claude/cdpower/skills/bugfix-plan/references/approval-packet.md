# Bugfix Approval Memo

신규 bug는 `workplan_schema: approval-memo-v1` main에서 다음만 짧게 보여 준다.

1. 증상과 이유: 관찰된 실패, 기대 동작, 확인된 원인 또는 남은 불확실성
2. 핵심 before/after: 파일·심볼·caller가 보이는 실제 코드
3. 변경 범위: 수정 파일·심볼과 유지할 정상 동작
4. 제외 범위: 건드리지 않을 저장소·계약·cleanup
5. 최소 검증: 수정 전 실패/수정 후 통과할 직접 test와 필요한 추가 확인
6. 승인: revision과 구현 시작 여부

원인이 여러 경로에 걸친 버그는 선택적 `## 구현 구상`에 증상별 수정 코드를 이어서 보여 준다. 현재 코드에서 어떤 값·분기가 문제인지, 제안 코드가 다른 caller·화면에 어떻게 전달되는지, 기존 호출을 무엇을 제거하는지와 회귀 테스트를 함께 적는다. 코드 fence는 실제 대상 언어를 사용하며 불확실한 API를 완성 코드처럼 쓰지 않는다. 한곳을 고치는 버그에 이 형식을 강제하지 않는다.

핵심 코드의 분량을 줄여도 원인을 제거할 설계를 구현 단계로 넘기지 않는다. [승인 전 설계 완료 판단](../../../references/implementation-handoff.md#승인-전-설계-완료-판단)은 본문 스킬의 필수 기준이며 이 예시의 사용 여부와 관계없이 적용한다.

코드가 길어 main의 판단 가능성을 떨어뜨릴 때만 `Details/plan-code.md`를 연결한다. 구현 결과, 지식 평가와 전체 diff는 계획에 미리 쓰지 않는다.

새 메모의 `## 검증 계획` 표에는 실패 조건, 기존/신규 테스트 파일과 이름, 실행 명령, 수정 후 통과 기준을 한 행으로 기록한다. 제외한 검증과 이유도 한 줄로 적어 승인안에 함께 보여 준다.

레거시 `scope-v2|scope-v3` 승인 패킷은 이미 승인된 Workplan에서만 그대로 읽는다.
